# TradeCore

**TradeCore** — локально разворачиваемая система управления товарами, складскими остатками и заказами для оптовой торговой компании.

Проект разрабатывается как полноценное fullstack-приложение: backend предоставляет версионированный REST API, frontend представляет собой отдельное SPA-приложение на Vue 3 и TypeScript.

> **Статус:** проект находится на начальном этапе разработки. Laravel-приложение и локальная Docker-инфраструктура подготовлены. Бизнес-функциональность и frontend будут реализовываться поэтапно.

## Цели проекта

- Продемонстрировать разработку и проектирование REST API на Laravel.
- Реализовать связанные бизнес-процессы каталога товаров, складского учёта и заказов.
- Продемонстрировать работу с транзакциями, конкурентным доступом к данным и целостностью остатков.
- Реализовать отдельный SPA-клиент на Vue 3 и TypeScript.
- Покрыть критичную бизнес-логику автоматизированными тестами.
- Обеспечить воспроизводимое локальное окружение с Docker Compose.

## Функциональные модули

В рамках проекта предусмотрены три бизнес-модуля.

### 1. Product Catalog

- Категории товаров.
- Товары.
- Единицы измерения.
- Цены товаров.
- Поиск, фильтрация и сортировка.

### 2. Warehouse & Inventory

- Несколько складов.
- Учёт складских остатков.
- Регистрация поступления товаров.
- Списание товаров.
- Перемещение товаров между складами.

### 3. Sales & Orders

- Клиенты.
- Создание заказов покупателей.
- Позиции заказа.
- Проверка доступности товаров.
- Управление статусами заказов.
- Отгрузка товаров.
- Отмена заказов.

### Сквозной бизнес-сценарий

1. В каталоге создаются товары и категории.
2. Сотрудник регистрирует поступление товаров на склад.
3. Система обновляет остатки.
4. Менеджер создаёт заказ покупателя.
5. Система проверяет доступность товаров и фиксирует операцию в соответствии с правилами складского учёта.
6. Склад выполняет отгрузку.
7. Система обновляет остатки и статус заказа.

## Общие возможности

Помимо трёх бизнес-модулей, приложение будет включать общие механизмы, необходимые для работы системы:

- аутентификация пользователей через Laravel Sanctum;
- разграничение доступа на основе ролей и Laravel Policies;
- уведомления о значимых операциях;
- аудит критичных изменений, если он требуется соответствующим бизнес-сценарием.

Эти механизмы не выделяются в самостоятельные бизнес-модули.

## Инженерные задачи

Основной акцент делается не на количестве CRUD-операций, а на корректности бизнес-логики и качестве реализации.

В проекте планируется продемонстрировать:

- разделение ответственности и Dependency Injection;
- Laravel Form Requests, API Resources, Policies и middleware;
- транзакционное выполнение складских и заказных операций;
- защиту от некорректного конкурентного изменения остатков;
- блокировки строк и ограничения целостности PostgreSQL там, где они необходимы;
- идемпотентную обработку повторных запросов для критичных операций;
- индексы и оптимизацию SQL-запросов;
- асинхронную обработку задач через Redis и Laravel Queues;
- события, уведомления и real-time обновления;
- автоматизированные тесты бизнес-ограничений и пользовательских сценариев.

Архитектура будет опираться на стандартную структуру Laravel. Дополнительные классы Actions, Services, DTO и другие абстракции будут вводиться там, где они упрощают сопровождение и тестирование, а не ради формального применения паттернов.

## Границы проекта

TradeCore не является полноценной ERP или CRM. В текущий объём не входят закупочные процессы и управление поставщиками, бухгалтерский и финансовый учёт, платежи, биллинг, полноценная CRM, multi-tenancy, мобильное приложение и AI-функциональность.

Такое ограничение позволяет сосредоточиться на трёх взаимосвязанных модулях и качественной реализации основного бизнес-сценария.

## Требования для локального запуска

- Git
- Docker Desktop с Docker Compose v2
- WSL2 с Ubuntu (для разработки под Windows)
- GNU Make

PHP, Composer, Node.js, npm, PostgreSQL и Redis устанавливать непосредственно в WSL не требуется: они запускаются в контейнерах.

## Установка и запуск

Все команды ниже выполняются из корня репозитория в WSL/Ubuntu.

### 1. Клонировать репозиторий

```bash
git clone <repository-url> trade-core
cd trade-core
```

### 2. Создать локальный файл окружения

```bash
cp .env.example .env
```

Проверьте параметры подключения к сервисам в `.env`:

```dotenv
APP_NAME=TradeCore
APP_URL=http://localhost

DB_CONNECTION=pgsql
DB_HOST=database
DB_PORT=5432
DB_DATABASE=trade_core
DB_USERNAME=trade_core
DB_PASSWORD=secret

REDIS_CLIENT=phpredis
REDIS_HOST=redis
REDIS_PORT=6379
```

`APP_KEY` будет сгенерирован на одном из следующих шагов. Не добавляйте `.env` и реальные секреты в Git.

### 3. Проверить конфигурацию Docker Compose и собрать PHP-образ

```bash
make config
make build
```

### 4. Установить frontend-зависимости

Если в репозитории есть `package-lock.json`, используйте воспроизводимую установку:

```bash
make npm-ci
```

Если lock-файл ещё не создан, выполните:

```bash
make npm-install
```

После первоначальной установки `package-lock.json` следует сохранить в Git. В дальнейшем используйте `make npm-ci`.

### 5. Запустить контейнеры

```bash
make up
make ps
```

Дождитесь состояния `healthy` у PostgreSQL и Redis.

### 6. Установить PHP-зависимости

```bash
make composer-install
```

### 7. Сгенерировать ключ Laravel

Если `APP_KEY` в `.env` пустой:

```bash
make key
```

### 8. Выполнить миграции и проверить приложение

```bash
make migrate
make artisan ARGS="about"
make test
```

После запуска приложение будет доступно по адресу `http://localhost:8080`.
